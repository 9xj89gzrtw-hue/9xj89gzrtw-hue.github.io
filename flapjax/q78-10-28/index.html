1. What was queried

The day in COT (UTC-5) is 05:00:00Z on 2026-10-28 to 05:00:00Z the next day. Mapping those two timestamps to block numbers on BSC gives 130221520 (first block at or after the start) and 130413457 (last block before the end), i.e. 191,938 blocks. A Transfer log filter was run over that whole range — in 20,000-block chunks, not sampled — for the FLAPJAX contract with the treasury as the from topic, and again with the treasury as the to topic. Both scans returned 0 events, on every chunk.

2. Why this is a zero and not a hole in the data

  • The same query returns non-zero on a day that had payments. The identical filter over 2026-10-29 COT (beginning at block 130,413,458) returns 15 transfers worth 5,095,000 FLAPJAX — see the 10-29 page. So the topic encoding, token address and RPC path are known-good; only the day differs.
  • The node refuses ranges it cannot serve instead of returning empty. Asked for a range it does not keep, the same endpoint answers Archive requests require a personal token — an error, not an empty array. Every chunk of 2026-10-28 came back as a valid empty result, and the raw response for each chunk was written to the JSON file linked at the bottom.
  • Both directions are empty. No FLAPJAX entered the treasury either, so this is not a day when the treasury was quietly refilled and paid out through another address; the token balance is unchanged across the window because nothing moved.
Because there were no transfers, there are no recipients and therefore no first-BNB-funder groups to report for this date: the grouping question is empty. I am not padding this page with a grouping of addresses that were not paid on 2026-10-28. The adjacent days are covered separately: 10-28 and 10-29.
